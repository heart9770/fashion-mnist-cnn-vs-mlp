# 实验结果说明

本目录是训练脚本输出的原始结果，由 `train\_fashion\_mnist.py` 写入。


文件一览

|文件|内容|
|-|-|
|`main.json`|主实验（4 组配置 × 3 个种子 × 12 轮）：汇总指标、每次运行的明细、每个 epoch 的损失与准确率|
|`small.json`|小样本实验（每类 100 张，共 1000 张，30 轮）|
|`long.json`|延长训练对照（30 轮，2 个种子）|
|`summary.json`|上面三个文件的精简版，只保留关键指标，方便快速查看|
|`preds\_best.npz`|主模型在测试集上的预测结果（NumPy 压缩包），用于错误分析|

## 四、关于 JSON 的“一行一行”

打开 `main.json` 会看到许多行只有一个数字，这**不是格式错误**。该文件用 `indent=2`
保存，所以每个数组元素单独占一行：12 轮的验证准确率就是 12 行，10×10 混淆矩阵的
100 个格子就是 100 行。

这样做有两个原因：

1. JSON 是给程序读的数据交换格式，标准本身不规定行怎么排；`json.load()` 解析出来的
结构与紧凑写法完全一致。
2. 每个数字独占一行，GitHub 的 diff 才能精确显示“哪一个格子变了”，便于版本对比。

人眼阅读请看上文的表格，或者 `summary.json`：只保留关键指标，约 100 行，比 `main.json` 短 30 多倍。

## 五、如何复现

见仓库根目录的 `README.md` 与 `REPRODUCE.md`。最快的办法是双击 `run\_verify.bat`，
或者执行：

```bash
python train\_fashion\_mnist.py --out results\_check --epochs 12 --seeds 42
python verify\_repro.py --new results\_check --tol 0
```

四行都显示“一致”，说明结果可以逐位复现。
